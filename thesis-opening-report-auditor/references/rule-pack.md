# 开题报告审阅规则包

本规则包服务于开题报告及开题相关文档，只定义审阅方法、通用 DOCX 检查和规则配置机制，不把任何学校要求默认为普遍规则。正式学位论文优先使用用户指定的论文审核 Skill；若用户明确要求本规则包参与，只能作为补充检查，不能把开题报告规则迁移到论文。学校/院系要求必须作为本次审阅的输入提取为规则档；当前用户明确要求和文档中已经确认的保护项优先于已选规则档。发现来源冲突或证据不足时，报告为“需确认/未配置”，不要擅自改写内容。

## 0. 外部资料与规范边界

以下资料可用于发现候选检查项、解释 Word 字段机制或追踪标准状态，但不自动成为本次审阅的学校规则。只有用户提供、指定或明确确认的学校/院系要求来源，才能激活学校专属门槛：

- [中国地质大学（北京）研究生学位论文开题暂行管理办法](https://graduate.cugb.edu.cn/c/2021-06-28/695241.shtml)：开题报告内容组成、硕士/博士字数与近 10 年参考文献数量要求。
- [中国地质大学（北京）研究生学位论文开题报告编写提纲（官方 PDF）](https://graduate.cugb.edu.cn/upload/resources/file/2024/01/25/240185.pdf)：开题报告章节结构与提纲示例。
- [Microsoft：Create a cross-reference](https://support.microsoft.com/en-us/word/create-a-cross-reference)：交叉引用以字段保存，并依赖隐藏书签/目标对象。
- [Microsoft：Add, format, or delete captions in Word](https://support.microsoft.com/en-us/word/add-format-or-delete-captions-in-word)：题注编号由字段生成，题注移动/删除后需要更新字段。
- [Microsoft Learn：Word processing / Open XML](https://learn.microsoft.com/en-us/office/open-xml/word/overview)：DOCX 是由多个 WordprocessingML 部件组成的 OPC 包，检查不能只限于正文段落。
- [国家标准全文公开系统：GB/T 7714](https://openstd.samr.gov.cn/bzgk/std/std_list?p.p1=0&p.p2=GBT+7714&p.p90=circulation_date&p.p91=desc)：可用于核对用户/学校指定版本的现行状态；标准状态查询本身不等于学校已指定该版本。

## 0.1 学校要求输入契约

每次审阅至少建立两类输入：

| 输入 | 可接受形式 | 用途 | 缺失时的处理 |
|---|---|---|---|
| 报告文档 | `.docx` | 检查正文、字段、题注、批注、版式和内容 | 无法审阅 |
| 学校要求来源 | 学校/院系模板 `.docx`、官方通知/指南 `.pdf`、官方网页 URL、用户提供的文字/表格/JSON | 确定学校专属格式、内容、字数、文献数量、GB/T 版本和提交门槛 | 相关项目标记“未配置/未判定”，不推测 |

可选但建议一并提供：学校名称、院系/专业、学位层次（硕士/博士）、报告类型、规则版本或生效日期，以及用户本轮明确的保护项和视觉例外。

学校要求提取记录至少包括：

| 字段 | 要求 |
|---|---|
| `source` | 文件绝对路径或官方 URL |
| `scope` | 学校、院系、专业、学位层次、报告类型 |
| `version/effective_date` | 来源标明的版本/生效日期；没有则写“未标明” |
| `evidence` | 原文条款、表格行、页码或网页段落 |
| `rule` | 转换后的可检查规则，例如最低字数、最低文献数、题注位置 |
| `machine_checkability` | `machine`、`partial` 或 `manual` |
| `confidence` | `high`、`medium` 或 `low` |

规则优先级固定为：当前用户明确要求 > 用户提供并确认的学校/院系要求 > 用户指定的官方学校来源 > 通用 Word/学术结构规则 > 外部搜索发现的资料。外部资料可帮助提出“建议核对”，但不能单独生成学校专属问题。

如果学校要求来源缺失、无法访问、只有扫描图片或存在冲突：

- 仍可执行通用 DOCX 结构检查，例如字段是否存在、引用是否为交叉引用、题注是否为 `SEQ` 域、批注/修订是否残留；
- 学校专属检查项必须列入“未配置/需确认”清单，不得给出通过/不通过的学校结论；
- 不得因为“CUGB”出现在文件路径、课题名称或历史经验中就启用 CUGB 规则；
- 若多个来源冲突，记录每个来源和冲突条款，优先采用明确标注为现行且适用范围更窄的来源，但在无法确认时保持 `needs_confirmation`。

## 1. 问题编号与严重度

| 编号前缀 | 类别 | 典型问题 |
|---|---|---|
| DOC | 文档/版式 | 页面尺寸、页边距、页眉页脚、字体、字号、行距、段落缩进、目录 |
| REQ | 规则配置 | 学校要求缺失、来源冲突、版本/生效日期不明、规则抽取置信度不足 |
| STR | 结构/内容完整性 | 开题报告必要章节、字数、参考文献数量、研究内容与计划要素缺失 |
| TOC | 标题/目录/编号 | 标题样式、大纲级别、编号跳级、目录条目或页码未同步 |
| REF | 引用/参考文献 | 文献编号缺失、未引用、引用为普通文本、交叉引用目标错误、文献表编号/格式异常 |
| CAP | 图表题注 | 题注不是 `SEQ` 域、样式不统一、编号不连续、正文引用不到题注 |
| EQ | 公式/符号/单位 | 公式编号、公式引用、符号首次定义、量纲/单位和公式断行 |
| ABB | 缩写 | 首次未给全称、后续重复写全称、同一缩写多种写法、大小写不一致 |
| ENG | 英文与空格 | 中英文/数字相邻空格不一致、中文标点前后空格、短语内部空格、单位/连字符/斜杠误处理 |
| PUN | 标点与字符 | 中英文标点混用、全角/半角异常、数字范围和连接号不统一 |
| CMT | 批注/修订/隐藏内容 | 残留批注、修改后没有批注、批注锚点缺失或重叠、修订未处理、隐藏文字 |
| SUB | 提交/元数据 | 文件名、格式、大小、作者信息、盲审隐私、文档属性和导出 PDF |
| PRO | 保护项/视觉例外 | 用户明确禁止修改的内容被改变，或用户认可的超宽/版式效果被擅自调整 |

严重度固定使用：

- `P0`：会破坏文档或字段关系，或导致提交版本无法可靠更新编号/目录。
- `P1`：明显违反学校格式或引用完整性，建议本轮修复。
- `P2`：一致性、可读性或常见规范问题，通常可批量修复。
- `P3`：仅建议优化、需要作者判断或属于文风偏好。

## 1.1 规则配置档

每次审阅先根据学校要求输入确定一个 `rule_profile`，而不是根据文件名或互联网搜索结果猜测：

- `general_academic_docx`：只使用通用 Word/学术规范，不推断学校专属数值。
- `cugb_opening_report_master`：仅在输入明确指向中国地质大学（北京）、学位层次为硕士且提供/确认适用的 CUGB 学校要求时启用。
- `cugb_opening_report_doctoral`：仅在输入明确指向中国地质大学（北京）、学位层次为博士且提供/确认适用的 CUGB 学校要求时启用。
- `custom_template`：以用户提供的学校模板、院系指南或规则 JSON 为准。

若学校要求、学位层次或适用范围不明确，使用 `general_academic_docx` 或 `custom_template` 的未配置状态，并在报告中列出未配置项目。不要把 CUGB 的字数、文献数、页码、GB/T 版本或题注位置自动套用到其他学校。

## 1.2 CUGB 开题报告可选检查

以下是 CUGB 专属规则档的候选条款，仅在学校要求输入明确确认其适用时生效；互联网检索到的 CUGB 页面不能单独激活本节：

| 检查项 | 硕士 | 博士 |
|---|---:|---:|
| 开题报告正文最低字数 | 5000 | 8000 |
| 近 10 年相关领域中外参考文献最低数量 | 30 | 50 |

内容结构至少应覆盖：文献综述（选题背景/项目依托、国内外研究现状、存在问题、研究目的或意义）；研究内容、拟解决问题、研究方法/技术路线和可行性分析；资料收集方法、时间与工作安排；预期目标或成果；参考文献。

字数和参考文献数量只做“是否达到门槛”的报告，不等同于内容质量评价；年份范围、文献相关性和中外文比例需要给出可核查证据或标为人工复核。

GB/T 7714 版本检查也必须以学校要求输入为准。只有学校要求明确写出 `GB/T 7714—xxxx` 或用户明确确认采用某个版本时，才核对版本适用性和条目格式；若学校要求没有指定版本，报告“版本未配置”，但仍可报告明显的结构性错误、编号断裂和字段/普通文本问题。

## 1.3 结构、目录与标题

- 检查封面/扉页的题目、姓名、学号、专业、研究方向、导师、培养单位等字段是否完整；同一信息在封面、摘要、页眉、正文标题和属性中是否一致。
- 检查必要章节是否存在，标题层级是否跳级、重复、编号冲突或混用手工编号和自动编号。
- 检查目录、图表清单、主要符号/缩略语表是否由域或模板生成，并在更新域后与正文标题、题注和页码一致。
- 目录或清单缺项时，区分“对象缺失”和“域未更新”；不要仅凭当前显示页码判断字段是否断链。

## 1.4 公式、符号、单位与脚注

- 公式应单独成行、按规则编号、编号位置一致；正文提到公式时应为交叉引用或至少有可追溯目标。
- 检查数学字体、上下标、变量斜体/正体、运算符、括号配对、公式断行和行间距；不把代码、寄存器名或协议字段误判为数学变量。
- 检查量和单位之间、数值精度、范围连接号、SI 单位、百分号和微秒等写法的一致性；按学校模板覆盖默认规则。
- 检查脚注/尾注编号连续性、引用锚点、正文与注释内容是否存在孤立项；脚注/尾注属于独立 OOXML 部件，不能只查正文。

## 1.5 图表和版心视觉风险

- 检查图表是否被裁切、超出版心、跨页断裂、题注与对象分离、表头未重复、行被不当拆分、图片分辨率或文字可读性不足。
- 图题通常置于图下、表题通常置于表上，但位置必须以选定学校模板为准；没有模板时只报告主导样式不一致。
- 检查表头的量纲/单位、图轴标题、图例、字号、来源说明和图中字体；图片内容不能只用段落文字审阅替代视觉检查。
- 用户确认“看起来超宽但视觉上可以”的对象记录为 `visual_exception`：冻结宽度、缩放、换行、位置和分页，不冻结题注文字或字段，除非用户另行明确禁止。

文献引用也属于视觉复核对象。Word 更新域并导出 PDF 后，必须检查正文所有含文献引用的页面，至少识别：

- `RS-485³`、`CAN⁴` 这类裸上标数字：REF 存在但可见方括号丢失；
- `[[3]]`、`[[5-6]]`：外层方括号与字段返回方括号重复；
- `[5]-[6]`、`[5][6]` 等本应为连续/并列引用但渲染结构异常；
- `[19]19 AUTHOR...`：文后列表编号与字段/手写编号叠加；
- 左右方括号、逗号、连接号与编号的上角标高度明显不一致。

视觉验收必须和 OOXML 验收同时通过。PDF 文本层可用于全量筛查括号和重复编号；一旦文本层不能可靠判断上标高度、字符是否被裁切或方括号是否实际可见，必须查看对应页面图像。只验证“Word 可打开/能导出/页数正常”不算完成视觉复核。

## 1.6 修订、隐藏内容、元数据与提交

- 检查 `w:ins`、`w:del` 等修订标记；不要擅自接受或拒绝修订，报告修订数量、作者和所在部件。
- 检查隐藏文字/对象、域代码显示状态、文档保护、不可见批注和批注锚点；无法确认最终打印效果时列为人工复核。
- 检查作者、最后修改者、公司名、文件路径、批注作者、修订作者等文档属性；盲审模式下单独报告个人信息风险。
- 若用户要求提交检查，另查扩展名、文件名规则、PDF 页数/大小、导出后字体和图片、空白页及关键页；提交规则没有依据时不得自动判定合格。

## 2. OOXML 字段判定

### 2.1 文献引用

优先识别复杂域：

```text
REF RefNum001 \\h \\* MERGEFORMAT
```

也检查 `w:fldSimple`，但要在报告中注明字段类型。以下情况分别处理：

| 现象 | 判定 |
|---|---|
| `REF RefNum###` 且目标存在 | 正常交叉引用 |
| 方括号内数字是普通 `w:t`，没有引用域 | `REF-01` 疑似非交叉引用 |
| `RefNum###` 指向不存在的参考文献 | `REF-02` 断链 |
| 正文引用了 `[n]`，参考文献表无 `[n]` | `REF-03` 引用无对应条目 |
| 参考文献表有条目但正文无引用 | `REF-04` 未引用条目；不删除 |
| 顺序编码制中，文后条目顺序与正文首次有效引用顺序不一致 | `REF-05` 顺序编码次序错误；必须生成首次引用序列验证，不能只看编号是否连续 |
| 同一文后条目同时存在自动列表、`SEQ RefList` 或手写编号中的两种及以上 | `REF-06` 参考文献编号结构异常；属于提交前必须修复的结构问题 |
| 学校/用户约定正文引用上角标，但 `[`、编号域、`]`、范围/分隔符任一部分未上标 | `REF-07` 正文引用上角标不完整 |
| 一处引用包含多个域/范围 | 作为一个引用标记报告，域逐个计数 |

顺序编码制的最低机器检查必须同时输出：

```text
first_occurrence_order
expected_order = [1,2,...,N]
order_ok
uncited_entries
duplicate_number_sources
non_superscript_citation_tokens
```

其中 `order_ok=false` 时，即使文后表面显示 `[1]...[N]` 连续编号，也不能判为“正文与文后对应正常”。参考文献编号来源检查必须解析 `numbering.xml` 与 `document.xml` 的 `numPr`/`SEQ`/手写文本三类来源；不能把字段缓存中的数字误当成普通手写数字。

### 2.2 图表引用与题注

- 图题、表题的编号应来自 `SEQ 图` 或 `SEQ 表` 域；记录实际域指令、显示结果和题注样式。
- 正文图表引用应是 `REF Fig...`、`REF Tbl...` 或可追溯的 `_Ref...`/`PAGEREF` 域。普通文本“图 7”“表 3”只能报告为疑似静态引用。
- 分别检查图号、表号是否从 1 开始且连续；不要把图号和表号混在一条序列中。
- 题注样式、居中/字体等版式按学校模板判断；没有模板时只报告与全文主导样式不一致的对象。

### 2.3 上角标

若学校模板/用户要求文献引用采用上角标，或当前文档主导样式已经明确采用上角标：

1. 只处理正文范围，排除“参考文献”标题之后的文献表。
2. 只处理 `RefNum` 域及其方括号、范围连接号和分隔符。
3. 保留域结构和交叉引用目标，不把编号替换为静态数字。
4. 参考文献表编号、图表编号、页码域和普通正文数字不能上角标化。
5. 复核时同时检查字段数量、显示编号、上角标运行属性和文献表正常属性。

即使用户没有主动提出“上角标”问题，审核也必须执行该复核；学校模板未规定且文档主导样式无法判断时标记为 `needs_confirmation`，不得直接忽略。

## 3. 缩写与英文空格

### 3.1 缩写

为每个候选缩写建立首次出现记录：

| 字段 | 内容 |
|---|---|
| `term` | 全称或术语 |
| `abbreviation` | 缩写，保持大小写 |
| `first_location` | 首次出现位置 |
| `first_form` | 首次出现的实际写法 |
| `later_forms` | 后续所有写法 |
| `decision` | `正常`/`首次缺全称`/`后续重复全称`/`需确认` |

默认判定：首次出现应为“全称（缩写）”或“全称（英文全称，缩写）”；后续优先只用缩写。标准名、型号、单位和学校模板固定写法不按普通缩写强行改写。

### 3.2 英文空格

默认检查以下模式，但以文档主导风格和学校模板覆盖：

- 独立英文/数字词嵌入中文句子时，检查相邻两侧是否统一为一个半角空格。
- 中文逗号、句号、分号、括号等中文标点前不留空格；英文短语内部空格不能被拆散。
- `MIL-STD-1553B`、`RS-422/485`、`AXI4-Stream` 等连字符/斜杠内部不插空格。
- 数值、单位、百分号、微秒等按模板和术语习惯判断，不对所有数字做无差别替换。
- 括号内是否留空格须保持一致；英文全称与缩写之间的逗号、括号由语义决定。

报告至少给出一条例证，例如“原文：`中文AXI4-Stream接口`；建议：`中文 AXI4-Stream 接口`”，并注明是否已修改。

## 4. 内容保护项、视觉例外与版本规则

- 保护要求来自当前用户指令，必须原样记录在报告中；不要把某个历史案例中的对象名称写成永久保护项。
- `content_protected_items`：用户明确说“不要改/不变更”的内容、字段或批注。此类对象只能检查、报告，不能自动修改。
- `visual_exceptions`：用户确认某个看起来可能超出宽度、边界或版心的对象“视觉上可以”。此类对象只保护宽度、缩放、换行、位置和分页效果；题注文字、题注 `SEQ` 域、正文交叉引用、缩写和空格仍可按规则检查或修改，前提是用户没有另行禁止。
- 视觉例外不能被误报为“题注不可改”。例如表 3、表 6、图 6 或封面日期如果只是因为当前宽度看起来可以，应记录为视觉例外，而不是内容保护项。
- 若对象看起来超宽但用户尚未确认，列为 `DOC`/`CAP` 问题或 `needs_confirmation`，不要擅自压缩表格、图片或题注；用户确认后再转为视觉例外。
- 修改题注文字时，保持原有对象宽度和题注样式，并在修改后重新做 PDF 视觉复核；若新文字确实造成溢出，应报告而不是自动改变视觉例外的宽度。
- 修改前复制版本，推荐命名为 `原版本名+1`（例如 `V2.3 → V3`）；不要覆盖源文件。
- 版本复制后，只比较和修改目标版本；Word 导出 PDF 只能作为临时复核产物，不能替代目标 `.docx`。

## 5. 批注规则

每项实际修改至少关联一个批注记录：

```text
comment = {
  "location": "段落/表格/题注位置",
  "change_id": "问题编号",
  "text": "说明改了什么、为什么改、是否保留交叉引用"
}
```

推荐批注措辞：

- 文献上角标：`已将本段文献引用统一设置为上角标，并保留为 Word 交叉引用域。`
- 补回文献：`已补回文献[33]的 RefNum033 交叉引用，并将本段文献引用统一设置为上角标。`
- 缩写：`首次出现已保留全称，后续出现统一使用缩写。`
- 英文空格：`已按全文主导格式统一英文/数字与中文相邻空格；英文短语内部未拆分。`

## 6. 最低验证集

修改版至少验证：

- `REF RefNum###` 数量与 `[1..N]` 覆盖关系；无缺失或断链。
- 顺序编码制必须输出正文首次有效引用序列，且与文后物理条目顺序一一对应；首次引用序列必须严格为 `1..N`。
- 每条参考文献只能存在一种编号来源；自动列表、`SEQ RefList`、手写编号混用数量必须为0。
- 若适用上角标规则，正文每一个文献引用 token 的方括号、字段结果和范围/分隔符必须全部为上角标。
- Word/PDF视觉结果中不得出现裸上标编号、缺方括号、双方括号、异常范围/并列引用或文后双编号；正文含引用页面必须完成全量视觉筛查，不能只抽查第一页和参考文献页。
- 参考文献表编号连续，且文献表编号没有上角标属性。
- 全部题注的 `SEQ` 域、显示编号和图/表序列连续。
- 图表引用不被误判为文献引用。
- 缩写首次/后续规则和英文空格问题均有证据。
- 源文件未改，目标文件可由 `python-docx` 打开；Word 只读导出可用时再检查 PDF 页数、纸张尺寸和关键页。
- 保护项未改变，已有批注保留，新增批注数量与修改对象对应。
