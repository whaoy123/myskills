# Thesis Opening Report Auditor

用于中文 `.docx` 学位论文、开题报告和类似学术报告的提交前格式审阅。它把“结构检查”和“内容不变的格式修复”分开，尤其适合检查 Word 中看起来像编号、但实际不是交叉引用或题注域的情况。

本技能不是通用学校规范的硬编码清单。标准输入由报告 `.docx` 和一份学校要求来源组成：学校模板、院系指南/通知、官方网页或 PDF、用户提供的文字/表格/JSON 规则均可。学校要求来源缺失时仍可执行通用 DOCX 结构检查；学校专属的 GB/T 版本、字数、参考文献数量、章节完整性、题注位置、页码和提交门槛统一标记为“未配置/未判定”，不得凭互联网搜索结果或其他学校规则自动判定。

## 文档类型与其他 Skill 的分工

- 本技能的主适用对象是开题报告、开题申请/考核材料、开题报告模板及其修改副本；“开题报告”的字数、参考文献数量和内容完整性规则只在相应学校规则档激活后使用。
- 正式学位论文（硕士论文、博士论文、学位论文全文）优先直接使用用户另行指定的论文检测 Skill。该 Skill 应负责论文专属的章节结构、学校论文模板、论文页眉页脚、摘要/关键词、目录、参考文献和提交要求。
- 如果用户明确要求本技能参与正式学位论文复核，本技能只作为补充检查器，重点检查 OOXML 交叉引用、题注域、批注/修订、缩写首次定义和英文空格；必须另行接收论文适用的学校要求，不能把开题报告规则档迁移到论文。
- 无法确认文档是开题报告还是正式论文时，先按通用 DOCX 结构检查并在报告中标记文档类型待确认；不得自动启用 CUGB 开题报告档。

## 工作模式

- 用户说“检查/审阅/找问题”时，默认只读，不修改源文档。
- 用户明确说“修改/修复/转换”时，先复制源文档到用户指定的版本名，再只修改复制件；源文件必须保留不变。
- 未明确指定输出版本且版本名存在歧义时，询问一次；若用户已给出明确的版本链（例如 V2.3 → V3），直接按该链执行。
- 用户给出的保护要求优先级最高，但必须区分“内容保护项”和“视觉例外项”。只有用户明确说内容/字段不能改的对象才属于内容保护项；用户仅确认“看起来超宽但视觉上可以”的对象属于视觉例外项，保留宽度、缩放、换行和位置，但仍可检查或修改题注文字、引用字段等内容。
- 修改模式下，每个实际修改的段落或对象都要有 Word 批注；同一段落内的同类批量修改可共用一个段落级批注。已有批注必须保留，不能用清理批注代替修复。

## 用户确认的版本模板与文字排版约定

当用户明确指定某个历史版本作为当前报告的格式基准（例如本项目的 V1.0）时，将该版本登记为当前报告的局部模板规则，并在后续检查和修改中优先执行：

- 参考文献表应复刻基准版本的原生 Word 编号结构。以本项目 V1.0 为基准时，每条文献使用同一编号列表段落（`List Paragraph` + 对应 `numPr`），编号格式为方括号十进制编号，从 `[1]` 起连续递增；不得把编号改成普通段落中的手写文本，也不得出现跳号、重复号或断号。
- 参考文献段落的左缩进、悬挂缩进、首行设置、段前段后间距、行距、对齐方式和字体继承关系应以基准版本的实际 `paragraph_format`、`styles.xml` 和 `numbering.xml` 为准，不凭经验重新设置。新增、删除或重排文献后，要同步验证编号列表和正文引用域。
- `numId`和`pStyle`的数值都是单个DOCX内部的本地标识，跨版本不能按相同数值直接复用。修改前必须沿着`w:num(numId)`→`w:abstractNum(abstractNumId)`核对0级定义的`start`、`numFmt`、`lvlText`、左缩进和悬挂缩进；同时按样式名称在目标文档中解析`List Paragraph`的实际`styleId`。
- 若目标文档中同名`numId`绑定了不同定义，必须从基准版本克隆完整的`w:abstractNum`和`w:num`为目标文档中的新、唯一实例，再将参考文献`numPr`绑定到该新`numId`；不得覆盖目标文档现有编号实例，以免影响正文、标题或其他列表。基准为本项目V1.0时，0级定义必须是：起始`1`、十进制、`lvlText="[%1]"`、左缩进`420`、悬挂缩进`420`。
- 修改后不只检查“存在numPr”：还要验证所有参考文献指向同一新编号实例、该实例的0级定义与基准一致、参考文献段落在目标文档中解析为`List Paragraph`、手写`[n]`前缀为零，以及DOCX可正常开包。若无法更新Word域或视觉渲染，明确报告该限制，不能宣称已凭`numId`一致完成格式复刻。
- 用户确认“中文与英文之间不留空格”时，该规则覆盖本技能中的默认英文空格建议：对正文、表格、图题、参考文献、页眉页脚和批注中的中英文相邻边界删除半角空格，例如 `Ethernet接口`、`1553B总线`、`MIL-STD-1553B测试`。只删除中文字符与英文字母相邻处的边界空格；英文短语内部空格、URL、文件路径、代码、单位表达和引用字段内部空格按语义保留。
- 修改前先提取并记录基准版本的编号与段落格式证据；修改后同时检查可见编号、编号域/列表属性、正文引用目标和中英文边界，不能只凭 `python-docx` 的纯文本结果判定通过。

## 学校要求输入契约

- 先接收并登记：报告文件、学校要求文件/链接/文本、适用学校、学位层次、院系/专业（如有）以及规则版本或生效日期（如有）。
- 学校要求来源可以是 `.docx` 模板、`.pdf` 通知/指南、官方网页、用户粘贴的要求，或结构化规则 JSON。若来源是扫描件、无法访问或表述有歧义，记录提取置信度和待确认项，不把推测写成规则。
- 规则优先级固定为：当前用户明确要求 > 用户提供并确认的学校/院系要求 > 用户指定的官方学校来源 > 通用 Word/学术结构规则 > 外部搜索得到的背景资料。外部资料只能帮助发现候选检查项，不能单独激活学校专属规则。
- 先从学校要求中提取 `rule_profile`，再审阅报告；提取结果应记录来源、适用范围、版本/生效日期、原文证据、机器可检验条件和人工复核条件。发现多个来源冲突时报告冲突，优先使用明确标注为现行且适用范围更窄的来源，并要求确认。
- `cugb_opening_report_master` 和 `cugb_opening_report_doctoral` 仅在输入明确指向中国地质大学（北京）且提供/确认 CUGB 学校要求时启用；不得因为文件路径、课题名称或互联网检索结果自动启用，也不得将 CUGB 数值套用到其他学校。

## 标准流程

1. 先判断文档类型：开题报告由本技能处理；正式学位论文转由用户指定的论文 Skill 处理，或仅在用户明确授权时进入补充复核模式。
2. 读取 [references/rule-pack.md](references/rule-pack.md)，登记报告和学校要求输入，提取学校规则并确定 `rule_profile`、适用范围、来源和置信度。
3. 建立输入文件清单和版本指纹，记录源文件、学校要求来源、目标文件、是否存在批注、页数/节数以及是否有表格和图形。
4. 提取正文、表格、题注、参考文献和 Word 字段。普通文字可用 `python-docx`，交叉引用、题注、批注和复杂域必须同时检查 `word/document.xml`、`word/comments.xml` 等 OOXML 部件；有条件时还要检查 `styles.xml`、`numbering.xml`、页眉页脚、脚注/尾注、设置、绘图/文本框和各部件的关系文件。
5. 检查以下问题组：文档/版式、学校要求配置与内容完整性、目录与标题、引用/参考文献、图表题注、公式/符号/单位、术语/缩写/英文空格、批注/修订/隐藏内容、提交元数据与保护项。引用/参考文献检查必须额外执行三项结构性验收：①顺序编码制文后条目是否严格按正文首次有效引用顺序排列；②每条文后文献是否只有一种可见编号来源，禁止自动列表、`SEQ RefList`、手写编号混用；③正文文献引用标记是否按学校/用户约定完整设置为上角标（包括方括号、编号域结果和分隔符）。固定问题编号和判定边界见规则包。
6. 先生成只读审阅结果；只有在用户授权修改时，才执行复制、字段级修复、批注锚定和目标文件验证。
7. 修改后重新检查：正文引用是否仍为交叉引用、正文首次引用序列是否严格为 `1,2,...,N`、文后条目物理顺序是否与该首次引用序列一致、文献编号是否连续且只有一个编号来源、正文文献引用 token 是否按规则完整上角标、题注是否仍为 `SEQ` 域、参考文献表是否保持普通格式、保护项是否未改变、批注数量和锚点是否完整。
8. 尽可能用 Word 只读打开、更新域并导出临时 PDF 做视觉复核；不得用 Word 保存修改件作为首选写入方式，因为 Word 可能重写图片/EMF 等媒体。Word 自动化不可用时，必须报告限制，并至少完成 OOXML 结构校验和 `python-docx` 开包校验。

## 关键判定规则

- 文献正文引用优先认定为 `REF RefNum###` 交叉引用域。方括号中的普通文本数字属于“疑似伪引用”，不能悄悄替换成文字或新编号。
- 对顺序编码制，必须按正文 XML 实际顺序扫描每一条文献的第一次有效引用，生成 `first_occurrence_order`。文后参考文献的实体顺序必须与该序列一致；首次引用序列不是严格 `1..N` 时，不得仅因为文后编号连续而判为正常。
- 文后参考文献编号必须检查编号来源，而不是只检查可见数字。每条条目同时扫描 `w:numPr`、`SEQ RefList` 和段首手写数字/`[n]`；自动列表 + `SEQ`、自动列表 + 手写、`SEQ` + 手写任一混用都判为编号结构异常，即使当前缓存显示暂时“看起来正确”。
- 图表交叉引用与文献引用分开统计：`REF Fig...`、`REF Tbl...`、`PAGEREF`、`_Ref...` 不得被当作文献引用上标化。
- 文献引用转上角标时，只处理正文引用标记的方括号、编号域结果和范围/分隔符；参考文献表编号保持正常格式。不得把域替换成静态文本。
- 即使用户没有主动指出“正文引用没上标”，也必须按学校模板/用户约定检查现有引用 token 的 `w:vertAlign`。若约定要求上角标，则 `[`、字段结果、`]`、并列分隔符和范围连接符必须全部为 `superscript`；只上标数字而括号未上标也判为不通过。学校未规定且用户未确认时，将上标/非上标样式记为待确认，不擅自套用其他学校习惯。
- 题注应优先检查 `SEQ 图`/`SEQ 表` 域、题注样式、图表编号连续性以及正文引用目标；视觉例外题注仍要检查字段和文字，只是不自动调整其宽度、缩放、换行或位置。
- 目录、标题编号、图表清单和页码是字段关系的一部分：检查标题样式/大纲级别、编号是否跳级、目录条目是否与正文一致，以及更新域后的页码是否正确。
- 公式、符号、单位、脚注/尾注和表格单位不能只看正文纯文本；检查编号域、正文引用、符号首次定义、单位写法和跨页/断行效果。
- 缩写规则为“首次出现给出中文/英文全称并标注缩写，后续只使用缩写”。无法确定两个近似术语是否同一概念时，列为需确认，不自动合并。
- 英文空格不是无条件的全局替换：以学校模板或文档主体的主导约定为准。默认检查英文/数字独立词与相邻中文之间是否统一使用一个半角空格；中文标点前不留空格；英文短语内部、连字符、斜杠、单位和括号按语义处理。报告必须给出原文证据和建议规则。
- “编号存在”与“编号被正文引用”分别报告。参考文献表中存在但正文未引用的条目不删除，通常为中低严重度问题。
- 检查修订标记、隐藏文字、域代码显示、断链书签、无锚点批注、页眉页脚和文本框中的内容；不能因为正文段落检查通过就宣称整个 DOCX 通过。
- 学校要求输入必须单独审计：记录其来源、版本、生效日期、适用范围、提取证据和置信度。没有学校要求时，GB/T 7714 版本、字数门槛、参考文献数量、必要章节、题注位置和页码规则只能报告为“未配置/未判定”，不能把互联网资料、其他学校规则或历史项目经验当成当前学校要求。
- GB/T 7714 版本检查只有在学校要求明确指定版本，或用户明确确认要采用某一版本时才判定；否则可以报告参考文献的结构性问题，但不能擅自断言“应使用某个版本”。

## 固定交付物

审阅完成后，始终按 [references/report-template.md](references/report-template.md) 输出：

- `<文档名>_审阅问题表.md`：固定问题表、修改建议表、已确认正常项、保护项和验证记录。
- `<文档名>_审阅问题表.json`：与 Markdown 同一批结果的机器可读版本。
- 报告中必须包含学校要求来源、规则抽取状态、当前生效的 `rule_profile` 以及未配置/冲突的学校专属检查项。
- 若用户授权修改，另输出修改后的 `.docx`，并在报告中记录源文件、目标文件、实际修改数、批注数和未处理项。

最终答复只概述结果并链接实际文件；不得把“建议修改”写成“已修改”。
