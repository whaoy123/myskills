# 滴答清单总控调度中枢 (Dida Master Orchestrator)

本技能是滴答清单体系的**唯一顶层入口与总控导航中枢**。负责判断用户是在做局部任务操作，还是要求全局规划，并把意图分发给对应 Skill。

## 核心原则

1. **滴答清单是当前任务事实的唯一权威。**
   - 当前有哪些任务、是否完成、日期、父子关系、优先级等必须从滴答运行态读取。
   - 模型记忆、聊天上下文、GitHub 模板只能补充背景，不能证明任务完整。
2. **MCP / 一等连接器优先。**
   - 有可用 TickTick/滴答清单 MCP 或连接器工具时，必须优先使用它完成读写和 read-back。
   - `dida-cli` 只在没有可用连接器的本地环境中作为 fallback。
3. **局部操作局部读取，全局规划全量读取。**
   - “把拿伞改到周二”“这个任务完成了”之类只解析相关任务。
   - “帮我安排今天/这周”“我现在该干什么”“看看我全部任务”必须先扫描全部未完成任务，不能只看未来 7 天或依赖记忆。
4. **AI 负责规划，用户保有执行控制权。**
   - AI 可做 WBS 拆解、估时、DoD、依赖、优先级、任务池整理和周期复盘。
   - 除非用户明确要求具体时间块，**不要擅自生成 `10:30–11:15` 这类执行块**。
5. **耗时采用半小时粒度。**
   - 默认以 0.5h 为基本粒度向上取整；较大任务允许保留总估时并分多次执行。

## 全局规划前置 Gate

以下请求视为**全局规划**：

- “帮我安排今天 / 明天 / 这周 / 下周”；
- “现在该做什么”；
- “看看我所有任务怎么安排”；
- “把我之前排的任务整体整理一下”；
- 用户要求根据“已有任务”重新安排多个项目或多个日期。

在调用 planner 给出结论前，必须：

1. 枚举全部可访问清单/项目；
2. 拉取**全部未完成任务**并处理分页；
3. 不遗漏无日期任务、远期任务、waiting 项和必要父任务元数据；
4. 读取与规划有关的 fixed/protected 承诺、运行态 profile 和依赖规则；
5. 对每个可能受时间约束的任务检查：
   - hard deadline / due date；
   - remaining estimate；
   - hard / soft dependency；
   - 外部等待与 lead time；
   - 未来真实可用容量；
   - `latest_safe_start`（最晚安全启动时间）；
6. 如果信息不足以判断最晚启动时间，明确标记“启动风险未知”，而不是因为截止日很远就忽略。

只有完成这一 Gate，才能从全局任务池中挑选今天/本周应执行的内容。

## 最晚安全启动时间

`latest_safe_start` 用于解决“任务截止很远，但实际上必须很早开始”的漏排风险。

计算/判断时至少考虑：

```text
硬截止
- 自身剩余工作量
- 必须串行的前置任务
- 审核/采购/打样/物流/预约/等待反馈等 lead time
- 风险 buffer
- 截止前不可用时间与容量限制
= 最晚仍能安全开始的窗口
```

如果任务有交付链，例如“设计 → 审核 → 打样 → 物流 → 现场使用”，不能只按最后交付日排序。

## 当前分类约定

在用户没有给出新的归类规则时，沿用当前主要工作域：

- **1553B 课题**（研究生）
- **AVRplus / 南航发电机相关**（研究生）
- **Verilog / RTL 学习**（研究生）
- **数字 IC 找工作与项目准备**（工作）
- **485 相关工程与 TB**：按当前运行态归档规则处理，不凭 Skill 静态文本强行移动已有任务
- **个人 / 健康 / 琐事**：按当前项目结构与用户已有分类放置

如果运行态项目结构与这里不同，以滴答当前结构和用户最新指令为准。

## 子任务命名

项目型子任务优先使用：

`父任务简称｜子任务具体名称`

例如：

- `调理隔离板｜完成最终接线表`
- `PCIe｜梳理分层与数据流`
- `1553B｜完成 BC 模块级仿真`

但不要为了格式统一强行重命名用户已经习惯的个人琐事。

## 意图路由

| 用户意图 | 核心 Skill / 动作 | 规则 |
|---|---|---|
| 拆解项目、细化任务、建立子任务 | `dida-task-breakdown` | 定义范围、DoD、依赖；必要时调用 estimator |
| 评估耗时、预估时间 | `dida-task-estimator` | 使用历史与风险缓冲，半小时粒度 |
| 全局安排今天/本周/下周、问现在做什么 | `dida-daily-planner` | **先通过本 Skill 的全量扫描 Gate**；没有明确时钟需求时只做日级/优先级规划 |
| 周复盘、清点任务池、检查延期风险 | `dida-weekly-review` | 应使用全量未完成任务视图，并检查 latest safe start |
| 快速记录新事项 | `dida-task-capture` | 重点做分类、去重、父子归属、waiting/executable 判断，再由 MCP 写入 |
| 汇报进度、实际花费 X 小时、任务完成 | `dida-task-progress` | 更新状态、focus/实际耗时和 remaining work |
| 查看某个任务/某天已有安排 | MCP/连接器直查 | 范围明确时无需全量扫描 |
| 修改日期、完成、移动、评论 | MCP/连接器直接执行 | read-before-write，写后 read-back |

## Runtime I/O 协议

### 首选：MCP / 连接器

如果当前运行环境提供 TickTick/滴答清单工具：

- 搜索精确任务前可先使用 search；
- 全局规划必须使用能够覆盖全部未完成任务的项目/任务枚举方式，并处理分页；
- 写操作尽量携带 projectId + taskId；
- 写前读取当前对象，保留未指定字段；
- 写后重新读取确认保存结果；
- 超时或结果不明确时先读回，避免重复创建/重复评论。

### 回退：`dida-cli`

只有当前环境没有可用 MCP/连接器时，才调用 `dida-cli`。CLI 的认证和安全约束由该 Skill 自己负责。

## 配套数据

- **用户配置**：`dida-planning-profile`——作息、容量、移动权限、估时缓冲。
- **长期背景**：`dida-planning-memory`——只保存稳定规则/背景，不承担当前任务事实。
- **确定性算法**：`dida-planning-core`——估时、容量、依赖、迁移等辅助算法，可重建，不作为任务数据库。

## 完成 Gate

任何全局规划结论至少应能回答：

1. 是否扫描了全部未完成任务，而不是仅近期任务？
2. 是否存在截止日尚远但最晚启动时间已临近的任务？
3. 是否存在依赖或外部等待会吃掉交付余量？
4. 本周真实容量是否足够？
5. 哪些任务本轮没有安排，以及为什么？

无法回答这些问题时，不应声称“所有任务都已经安排到位”。
