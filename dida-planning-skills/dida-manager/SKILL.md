# 滴答清单总控调度中枢 (Dida Master Orchestrator)

本技能是滴答清单体系的**唯一顶层入口与总控导航中枢**。负责承接所有关于滴答清单的意图，贯彻全局工作流原则，并精准分发调度下层子技能。

---

## 🔒 全局核心第一原则（不可违背）

1. **AI 专精于架构与整理，具体执行由用户全权自主掌控**：
   - AI 负责：任务 WBS 拆解、估时标签、完成标准 (DoD)、子清单 Checklist、任务池整理与周期复盘。
   - 用户负责：每日根据自身状态与精力自主挑选任务，灵活推进。
   - **严禁擅自生成带具体时钟（如 `10:30-11:15`）的“执行块”占位**。
2. **四大主干体系强制归属**：
   - 🚀 **1553B 课题**（清单: `研究生`）➔ 子模块：开题报告、上位机与通信、1553B IP核与收发。
   - ⚡ **AVRplus 复刻**（清单: `研究生`）➔ 子模块：调理隔离板、Field 采样与励磁。
   - 📚 **Verilog 写法学习**（清单: `研究生`）➔ 子模块：common_cells、pulp_axi、taxi。
   - 💼 **数字IC 找工作**（清单: `工作`）➔ 子模块：UART/低速总线 IP核、PCIe、集创赛与 CPU 体系、前端交付流程。
   - 📦 **485 相关工程与TB** ➔ 必须独立归档于【研究生，任务归档】清单，绝不混入主线。
3. **统一子任务命名格式**：
   - 所有子任务统一使用 **`父任务简称｜子任务具体名称`** 格式（例如：`开题报告｜全文去重精炼`、`调理隔离板｜完成PCB设计`、`PCIe｜梳理分层与数据流`、`FPGA｜数字IC 设计的 PPA 优化`）。
4. **耗时标签规范**：
   - 统一使用 **半小时（0.5h）为单位向上取整** 标签：`#0.5h`, `#1.0h`, `#1.5h`, `#2.0h`, `#2.5h`, `#3.0h`。
5. **记忆任务物理隔离**：
   - 所有记忆/规则类任务（包含通用约定与项目专属规则）必须统一收拢于【系统配置】清单下的长期记忆父分类中，**严禁混入主线业务清单**（如 `研究生`、`工作` 等），确保任务列表纯净仅保留可执行打勾的行动项。

## 🧭 意图路由与子技能分发对照表

收到用户指令后，总控中枢按以下映射关系调度子技能：

| 用户的自然语言意图 | 调度的核心子技能 | 执行动作与职责 |
| :--- | :--- | :--- |
| **拆解项目 / 细化任务 / 任务划分 / 建立子任务** | `dida-task-breakdown` | 将大任务按四大主干拆解为原子任务，使用 `父任务简称｜子任务名称` 命名，定义 DoD，并调用 estimator 打上半小时标签 |
| **评估耗时 / 预估时间 / 大概多久** | `dida-task-estimator` | 读取技能栈与特征模型，评估耗时并输出 `#0.5h`~`#3.0h` 标签 |
| **复盘整理 / 归档完成任务 / 梳理任务池** | `dida-weekly-review` | 盘点当前进度、归档已完成项、清点未完成任务池 |
| **快速记录 / 随手记 / 收集箱待办** | `dida-task-capture` | 快速清洗输入并录入指定清单 |
| **推进进度 / 任务打勾 / 完成状态更新** | `dida-task-progress` | 更新任务状态与完成时间，维护父子任务进度 |
| **查看当前日程 / 查看安排情况** | `dida-manager` (直查) | 从本地 SQLite 数据库或 CLI 读取今日任务与待办清单直接呈现 |
| **【显式请求】帮我安排今天日程 / 排具体时间块** | `dida-daily-planner` | **仅在用户显式要求排期时调用**，调用作息模型给出时间块建议 |

## 🛠️ 底层支撑技能与数据接口

- **长期记忆**：`dida-planning-memory`（读取工位、技能栈背景、硬件项目规则）
- **用户配置**：`dida-planning-profile`（读取估时模型、作息规则、标签协议）
- **数据引擎与CLI**：`dida-planning-core`、`dida-cli`（本地 SQLite 数据库与 CLI 读写通信）
