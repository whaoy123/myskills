# DOCX Sequential Citation Rebuilder

用于修复 `.docx` 中采用**顺序编码制**的参考文献引用系统。核心目标不是“把数字改对”，而是恢复一个可继续由 Word 更新的、字段关系完整的引用系统。

本技能只处理参考文献编号、书签、交叉引用、正文引用显示格式以及与这些对象直接相关的段落顺序。参考文献题录真实性与 GB/T 7714 格式本身应交由相应 citation generator/auditor skill 处理；论文/开题报告的其他结构和内容问题仍由对应文档审核 skill 负责。

## 适用场景

当出现以下任一情况时使用本技能：

- 文后参考文献编号与正文首次出现顺序不一致；
- 更新 Word 域后出现 `[8] 8AUTHOR...` 这类双重编号；
- 正文 `[n]` 是手打文本而不是交叉引用；
- `REF RefNum###` 指向错误、缺失或编号已变化；
- 新增/恢复引用后，部分引用没有上角标；
- 文献重排后正文仍显示旧编号；
- `SEQ RefList`、Word 自动列表编号和手写 `[n]` 混用；
- 引用范围或并列引用在重编号后出现错序、漏号或重复。

## 非目标

- 不凭标题或上下文猜测缺失文献；
- 不擅自删除未引用文献，除非用户或学校规则明确要求；
- 不把 `REF`、`SEQ` 或 Word 列表编号转换为普通文本以“看起来正确”；
- 不顺带改写论文内容、文献题名、作者、年份、DOI；
- 不用 LibreOffice 另存后的结果作为 Word 字段结构正确性的唯一依据。

## 输入

至少需要：

1. 目标 `.docx`；
2. 用户确认的参考文献编号约定或学校模板；
3. 若存在历史正确版本，优先同时提供基准版本；
4. 用户对批注、修订、源文件保护、输出文件名的要求。

若没有学校模板或历史正确版本，仍可修复，但必须先识别当前文档实际使用的编号机制，不能自行把一种机制强制改成另一种。

## 修改模式

- 默认只修改副本，原文件保持不变。
- 用户要求“所有修改位置加批注”时，重排、字段重建、格式修复涉及的段落必须有批注；同一段落内同类批量修复可共用一条批注。
- 已有批注必须保留，除非用户明确要求删除。
- 在真正改写前先输出并保存一份 `old_ref -> new_ref` 映射表，后续所有字段修改必须基于该映射执行。

## 核心原则

### 1. 参考文献编号只能有一个来源

文后每条参考文献只能使用一种可见编号机制。允许的规范结构主要有两类：

**A. Word 自动列表编号**

- 参考文献段落通过 `w:numPr` / `numbering.xml` 产生 `[1]`、`[2]`……；
- 正文交叉引用通过指向该段落书签的 `REF ... \\r` 等方式取得段落编号；
- 文献正文中不得再出现 `SEQ RefList` 或手写 `[n]` 前缀。

**B. `SEQ RefList` 编号**

- 每条参考文献段首由 `SEQ RefList` 产生唯一编号；
- 该编号被 `RefNum###` 等书签包围；
- 正文用 `REF RefNum###` 取得编号；
- 参考文献段落不得同时挂产生同一 `[n]` 的自动列表编号，也不得保留手写数字。

优先级：**用户指定模板/历史正确版本 > 当前文档主导结构 > 通用建议**。

一旦识别为 A 或 B，整份文档必须统一。检测到 A+B、A+手写、B+手写任一组合时，先判为结构错误，修复后必须再次证明只剩一套编号源。

### 2. 新编号由正文首次出现顺序决定

顺序编码制的重编号基于正文中每条文献的**第一次有效引用位置**，不是原参考文献表顺序，也不是旧编号大小。

扫描范围默认从正文起始到“参考文献”标题之前，并排除：

- 文后参考文献自身；
- 目录缓存文本；
- 页眉页脚；
- 批注内容；
- 图表交叉引用 `REF Fig...`、`REF Tbl...`；
- 非文献书签。

得到顺序：

```text
old_ref_order = [old8, old3, old12, ...]
```

然后建立双射：

```text
old8 -> new1
old3 -> new2
old12 -> new3
...
```

同一文献后续再次出现不新增编号。

### 3. 以“文献实体”而不是旧数字作为重排身份

旧编号只是临时标识。修改前应为每条文献建立稳定身份，至少包含：

- 原段落 XML 节点；
- 原编号/书签名；
- 归一化后的题录文本摘要；
- 可选的 DOI、标准号或题名哈希。

重排时先确定“哪一条文献移动到哪里”，再更新编号与书签。不得只对字符串中的数字做全局替换。

## 标准执行流程

### 第 1 步：结构盘点

同时读取：

- `word/document.xml`
- `word/numbering.xml`
- `word/styles.xml`
- `word/settings.xml`
- `word/comments.xml`（如存在）
- 必要的关系文件

盘点并记录：

- 参考文献标题位置与条目数；
- 每条参考文献的编号来源：自动列表 / SEQ / 手写 / 混合；
- 所有 `RefNum...` 或对应文献书签；
- 所有正文文献 `REF` 域及字段结果；
- 正文中疑似手打的 `[n]`、`[n-m]`、`[n,n]`；
- 正文引用 run 的 `w:vertAlign w:val="superscript"` 状态；
- 是否存在隐藏文本 `w:vanish`；
- 是否存在 Word 修订 `w:ins` / `w:del`。

如果无法唯一识别参考文献区间或编号机制，停止自动重建并报告待确认项。

### 第 2 步：确定首次引用顺序

按文档实际 XML 顺序遍历正文文献引用。

必须区分：

- 单篇：`[8]`
- 并列：`[8,12]`、`[8][12]`
- 连续范围：`[8-10]`
- 同一文献重复出现

对于范围引用，必须解析其真实字段组成；若只是一个手写 `[8-10]`，先标记为伪引用，不能在不知道中间文献关系时直接推导。

生成并保存：

```text
first_occurrence_order
old_to_new
new_to_old
uncited_entries
unresolved_manual_citations
```

### 第 3 步：重排文后参考文献

按 `first_occurrence_order` 将已引用文献物理移动到新顺序。

未引用文献处理：

- 用户/学校要求“参考文献必须均在正文引用”时，先报告并按用户指示删除、补引或保留；
- 没有明确要求时，不擅自删除，统一放在已引用文献之后并标记为 `uncited`，等待用户决定。

重排必须移动完整段落及其 run、域、书签、超链接和段落属性，不能只复制可见文字。

### 第 4 步：重建编号与书签

根据选定的编号架构 A 或 B 执行。

#### 架构 A：自动列表编号

- 所有参考文献条目绑定到同一、正确的编号实例；
- 编号格式、起始值、悬挂缩进从模板/基准版本继承；
- 删除重复的 `SEQ RefList` 和手写编号；
- 每条文献建立唯一书签；
- 正文使用能返回段落编号的 `REF` 形式；
- 不覆盖文档中其他列表使用的 `numId`。

#### 架构 B：SEQ 编号

- 每条文献只保留一个 `SEQ RefList`；
- 第一个条目从 1 开始，后续连续；
- 每个 SEQ 编号由唯一 `RefNumNNN` 书签包围；
- 删除会重复显示编号的自动列表属性和手写数字；
- 所有书签 id/name 全文唯一。

无论 A/B，最终可见编号只能出现一次。

### 第 5 步：重建正文 REF 映射

对每个正文引用：

1. 根据旧文献实体找到新编号；
2. 更新 field instruction 中的书签目标；
3. 保留原有 `REF` 字段类型和需要的 `\\h`、`\\r` 等开关；
4. 更新字段缓存显示值；
5. 不把字段替换成静态数字。

如果一个引用由 `[` + field + `]` 三部分组成，三部分都属于同一个引用标记，不能只修改中间 field。

### 第 6 步：统一正文引用上角标

正文文献引用默认整体上角标化，包括：

- 左方括号 `[`；
- 编号 `REF` 字段；
- 右方括号 `]`；
- 并列引用的逗号、分号；
- 连续范围的连接符。

相关 run 应统一具有：

```xml
<w:vertAlign w:val="superscript"/>
```

不得把参考文献表中的编号上角标化。

若学校模板明确要求非上标引用，以学校模板为准，并在验收报告中记录例外。

### 第 7 步：字段更新策略

优先级：

1. 可用 Microsoft Word 自动化时，在副本上更新字段并验证显示；
2. 无 Word 自动化时，手工更新可安全确定的字段缓存，并把相关域设为 dirty/update-on-open；
3. 不使用 LibreOffice 的“另存为 DOCX”来证明 Word REF/SEQ 语义正确，因为它可能改写字段结构。

如果无法真正执行 Word 字段更新，最终结果必须明确标记：

```text
FIELD_CACHE_UPDATED_BUT_WORD_REFRESH_REQUIRED
```

并要求用户在 Word 中 `Ctrl+A` → `F9` 后再次检查。此时不能声称“Word 中最终显示已验证”。

如果能够用 Word 更新字段，则必须继续执行**引用视觉验收**，不能在字段更新成功后直接结束：导出 PDF，定位全部含正文文献引用的页面，核对可见 token 是否仍为预期的 `[n]`、`[n-m]` 或并列形式。重点抓 `RS-485³`/`CAN⁴` 裸上标数字、`[[n]]` 双括号、`[n]-[m]` 范围拆裂及文后 `[n]n` 双编号。PDF 文本层无法判断上标高度或括号可见性时，必须查看对应页面图像。

## 必做验收

修改完成后必须全部检查：

### A. 顺序编码验收

正文第一次出现的参考文献编号序列必须严格为：

```text
1, 2, 3, ..., N
```

允许同一文献后续重复，不允许首次出现序列为：

```text
1, 2, 8, 3, ...
```

这是强制 PASS 条件。

### B. 文后编号验收

- 编号从 1 连续到 N；
- 无重复号；
- 无漏号；
- 无 `[8] 8AUTHOR...` 双重编号；
- 每条只存在一个编号来源；
- 参考文献条目数与编号数一致。

### C. 交叉引用验收

- 所有正文文献引用仍是 `REF` 字段；
- 所有 `REF` 目标书签存在；
- 无正文引用指向旧书签；
- 无孤立 `RefNum...` 书签；
- 字段缓存与新编号一致；
- `REF Fig...` / `REF Tbl...` 等非文献引用未被修改。

### D. 上角标验收

对每个正文文献引用标记，检查整个 token 的 run properties：

- `[` 上标；
- field result 上标；
- `]` 上标；
- 分隔符/范围符号上标。

只要其中一部分不是上标，就不能判 PASS。

### D2. Word/PDF视觉验收

- 正文每个文献引用在 Word 实际渲染后必须能看到完整方括号；
- 不得出现只有上标数字而无方括号的 token；
- 不得出现 `[[n]]`、`[n]-[m]`（本应为 `[n-m]` 时）等字段更新后显示异常；
- 文后不得出现 `[n]n` 双编号；
- 视觉验收范围必须覆盖所有含引用页面，而非只抽查参考文献页；
- 该项失败时，即使 OOXML、书签和 REF 目标全部正确，最终状态仍必须为 `FAIL`。

### E. 伪引用验收

正文中不应再存在与参考文献编号匹配的普通手打数字引用，除非明确列入例外。

建议同时扫描：

```regex
\[[0-9]+(?:\s*[-,，;；]\s*[0-9]+)*\]
```

命中后必须进一步通过 OOXML 判断该数字是否由字段产生，不能只靠正则决定。

### F. 双重编号验收

对每条参考文献同时检查：

- `numPr`
- `SEQ RefList`
- 段首手写 `[n]` / `n`

只允许选定架构所需的一种编号源。发现第二种来源即 FAIL。

### G. 文档完整性验收

- `python-docx` 可打开；
- DOCX ZIP 可正常解包；
- XML 可解析；
- 书签 start/end 成对；
- 字段 begin/separate/end 结构完整；
- 原有批注数量不减少；
- 原有修订不被静默接受或删除；
- 源文件未被覆盖。

## 强制失败条件

出现以下任一情况，最终状态必须为 `FAIL`：

- 正文首次引用序列不是 `1..N`；
- 文后存在双重编号；
- 任一正文文献 `REF` 目标不存在；
- 任何已修复引用被转换成普通文本；
- 新增/重建引用未遵循模板规定的上标/非上标格式；
- 参考文献重排后题录与引用映射无法证明一一对应；
- 修改导致原批注、修订或其他非目标字段丢失；
- 只凭 PDF/LibreOffice 渲染“看起来正确”而没有 OOXML 结构证据。

## 推荐输出

最终报告保持简短，只给：

```text
模式：REBUILD
状态：PASS / PASS_WITH_WARNINGS / FAIL

统计：
- 参考文献：N 条
- 正文 REF：M 个
- 重编号：K 条
- 未引用文献：U 条
- 手打伪引用：0/...

结构：
- 编号架构：AUTO_LIST / SEQ_REFLIST
- 双重编号：0
- 缺失书签：0
- 首次引用顺序：1..N PASS
- 上角标完整性：PASS

需人工确认：...
输出文件：...
```

## 与其他 Skill 的协作

- `thesis-opening-report-auditor`：发现顺序编码、双重编号、伪引用、REF/上标问题后，可将**实际重建**交给本技能。
- `gbt7714-2015-citation-auditor` / `gbt7714-2025-citation-auditor`：负责题录格式与事实核验，本技能只负责 Word 编号系统和引用关系。
- `md-to-docx`：新生成 DOCX 时可借用本技能的验收规则，防止生成后再出现静态引用或双重编号。

## 最重要的验收原则

**“数字看起来对”不等于引用系统正确。**

只有同时满足以下四项才算完成：

1. 正文首次引用顺序严格为 `1..N`；
2. 文后编号只有一个来源且连续；
3. 正文引用仍是可更新的 Word 交叉引用；
4. 整个引用标记的显示格式与模板一致。
