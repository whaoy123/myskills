# Questa Wave Layout

这个 Skill 只负责一件事：

> 把已经确定需要观察的 RTL/TB 信号整理成用户容易看的 Questa 波形布局，并生成可直接使用的 `.do` 脚本。

它不负责判断 DUT 是否正确。正常验证仍以 TB 自动检查为准；波形主要用于首次验收和 Debug。

## 输入

优先读取：

1. DUT RTL；
2. TB；
3. `verification_plan.md`；
4. 如果存在，读取当前模块已有的 Questa `.do` 脚本；
5. 如果存在用户已经认可的波形布局示例，优先模仿这些示例。

## 输出

生成或更新一份 Questa 波形脚本，例如：

```text
run_questa_wave.do
```

要求：

- 打开后即可看到需要的关键波形；
- 信号已经按功能分组；
- 组内信号顺序应便于从输入事件追到输出结果；
- 不要求用户再次手工添加大量关键波形；
- 不默认把整个 DUT 层级全部加入波形窗口。

## 核心原则

### 1. 用户习惯优先

如果已有用户认可的 `.do` 文件或波形布局示例：

- 优先复用其分组名称；
- 优先复用组顺序；
- 优先复用组内信号排序习惯；
- 新模块只在确有需要时增加新的分组类型。

不要因为 AI 认为“更标准”就擅自重排已经确认的布局习惯。

### 2. 按阅读逻辑分组，不按 RTL 层级机械分组

波形分组服务于 Debug 和时序阅读，而不是复刻模块层级。

没有用户样例时，可以暂时参考下面的通用分类：

```text
Clock / Reset
Interface
Handshake / Control
Data
State / Counter
Error / Status
Internal Debug
```

这只是缺少用户样例时的默认兜底，不是固定模板。不同模块应根据实际职责调整。

### 3. 信号选择以验证点和 Debug 价值为依据

优先加入：

- 时钟、复位；
- 触发当前验证点的输入；
- 关键握手信号；
- 输出数据和状态；
- 状态机状态；
- 与关键时序直接相关的计数器；
- 错误状态；
- 能直接解释当前 Bug 根因的内部信号。

不要为了“看起来完整”加入大量没有诊断价值的内部寄存器。

### 4. 组内信号按事件传播顺序排列

一般按下面的阅读方向排序：

```text
触发输入
→ 握手/控制
→ 关键状态
→ 计时/计数
→ 数据
→ 输出/提交
→ 错误
```

如果用户已有明确习惯，以用户习惯为准。

### 5. 波形脚本不改变设计和验证语义

本 Skill 只能：

- 添加/删除波形观察项；
- 调整分组；
- 调整排序；
- 设置必要的 radix、展开层级和显示方式。

不得：

- 修改 DUT；
- 修改 TB 判定逻辑；
- 修改 assertion；
- 为了让波形好看而改变测试激励。

## 与验证流程的关系

推荐流程：

```text
verification_plan.md
        ↓
TB + 自动检查
        ↓
仿真通过 / Debug
        ↓
questa-wave-layout
        ↓
run_questa_wave.do
```

TB Skill 负责决定“验证什么、哪些信号对验证有价值”；本 Skill 负责决定“这些信号在 Questa 里怎么摆才好看、好查”。

## 第一版默认行为

当前还没有冻结用户最终的波形分组风格，因此：

1. 有历史样例时，先模仿历史样例；
2. 没有历史样例时，使用最少数量的功能分组；
3. 不为了整齐强行把所有模块套进相同模板；
4. 后续用户确认新的分组习惯后，应优先更新本 Skill 的正例，而不是在每个项目脚本里单独打补丁。
