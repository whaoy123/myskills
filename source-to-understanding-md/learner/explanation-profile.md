# Explanation Profile

这是 `source-to-understanding-md` 的持续风格状态。它记录“用户更容易怎么理解”，与 `knowledge.yaml` 的“用户已经知道什么”分开管理。

## 当前稳定偏好

1. **先整体，后局部。** 先给原文里的完整功能大图，说明当前功能在整块里的位置；再从大图中框出局部并放大。
2. **使用问题驱动的小标题。** 用户接受并偏好 `## 1. 这部分用到哪些输入`、`## 3. 为什么……`、`## 5. C7 是干什么的` 这类标题；不要把方法论直接写成“原文/原理/用途”三段模板。
3. **每一节只解决一个具体疑问。** 常用顺序：位置与目标 → 输入 → 完整电路 → 当前最难原理 → 参数/公式 → 正常工况量级 → 输出去向 → 系统作用。
4. **原图优先。** 默认截原文图片并编号/红框；简化图只在原图因果关系难读时补充。
5. **已学过的机制一句带过。** 例如再次出现理想二极管，直接说“和前面的 PEAK SENSE 同一个原理”，篇幅留给新差异。
6. **公式必须落到真实数值。** 符号公式 → 图中真实 R/C/阈值/频率 → 数值 → 解释物理意义。
7. **喜欢先理想化，再把真实元件加回来。** 先忽略某个电容/负载得到简单关系，再解释真实电路如何修正。
8. **关键前置条件单独解释。** 例如“三相原始正弦直接相加为什么为 0”“为什么先整流”，不能只给最终公式。
9. **参数选值要讲为什么。** 不满足于 `τ=RC`；说明太大/太小分别怎样，以及实际值落在哪个时间尺度。原厂未给设计指标时明确写“从电路反推”。
10. **需要正常工作点的量级校验。** 例如 `115 Vrms → 4.11 Vrms → 5.81 Vpk → 内部反馈约多少伏`，把公式和真实系统对应起来。
11. **保留实图、实值、实测，删重复说明。** 用户会保留 CMM 测试数据、门槛、滤波计算；会删除重复 ASCII 链、重复总结和不必要的上游追溯。
12. **语气中性工程化。** 避免“死命维持”“谁最危险先看谁”这类比喻，直接写控制含义。
13. **少写元话语。** 不写“最值得看的是”“这里特别关键的是”，直接进入条件、例子或推导。
14. **因果依据顺手写出。** 例如“因为虚短性质，这时…”，不要把依据和结论拆成重复两段。
15. **英文原文按需保留。** 网名、器件名、检索关键词保留；普通说明优先自然翻成中文。
16. **caveat 只保留一层。** 只有会改变工程判断的边界才写，并尽量一句话。
17. **结尾回到当前系统，不扩散。** 说明这条支路在 GCU 里具体改变什么，并和上一支路做很短的对照即可。
18. **用户编辑稿是最高优先级的风格证据，但技术正确性仍独立核对。**

## 当前最有代表性的直接编辑

- AVERAGE SENSE：问题式编号结构、先算输入量级、再拆完整电路、再推导、最后正常工况量级校验。
- Current Limit：保留真实参数和闭环测试，删除重复链路与口语比喻。
- VR_DISABLE / Soft Start：保留 KCL/斜坡计算，减少元话语和重复免责声明，直接写 D40/C13 的器件动作。
