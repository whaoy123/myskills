# PCB 焊接清单/焊接表制作 Skill

## 1. 目标

根据用户提供的原理图、BOM、PCB/装配图和旧版焊接表，生成一份可直接用于焊接、装配和焊点统计的 `.xlsx`。

本 Skill 的重点是：

- 器件型号、位号、数量准确；
- 封装写法简短、实用；
- 贴片焊点和直插焊点统计清楚；
- 表格风格统一、简洁；
- 不把测试点、网络标签等非焊接对象混入清单；
- 有疑问直接问用户，不把“待确认”堆到 Excel 里。

## 2. 输入资料优先级

信息来源按以下优先级使用：

1. **用户当前明确说明**：优先级最高，例如“固定脚算焊点”“测试点不算”“R1 是插件电阻”。
2. **完整 BOM**：用于确认型号、位号、数量、Footprint/封装。
3. **原理图**：用于核对 BOM 是否遗漏器件、确认引脚数、器件功能和连接器类型。
4. **PCB/装配图**：用于辅助确认连接器公母、器件安装形式、插件/贴片属性。
5. **旧版焊接表**：主要作为格式和统计口径参考。

如果 BOM 与原理图冲突，不要自行猜测。会影响最终焊接清单或焊点数时，直接向用户提问。

## 3. 生成前必须检查

正式生成前至少检查：

- BOM 中器件是否完整；
- 原理图是否存在 BOM 中没有的器件；
- 连接器的信号针数量；
- 是否存在固定脚/外壳脚；
- 测试点是否计入焊接；
- 插件电阻/电容等是否明确为直插；
- DNP/NC/Reserved 是否需要安装；
- 用户是否给出了特殊统计口径。

### 有疑问时的处理

**直接问用户，不新增“待确认” Sheet。**

例如：

> 原理图里有 R1=330mΩ，但 BOM 里没有。R1 是否需要焊接？如果需要，是贴片还是插件？

只有确认后再生成最终版。

## 4. 标准输出格式

### 4.1 工作表

默认只生成 **1 个 Sheet**：

`焊接清单`

除非用户明确要求，否则：

- 不生成“待确认” Sheet；
- 不生成“来源说明” Sheet；
- 不生成额外统计 Sheet。

### 4.2 固定列结构

统一使用以下 7 列：

| 位号 | 型号/规格 | 封装 | 数量 | 贴片焊点 | 直插焊点 | 备注 |
|---|---|---|---:|---:|---:|---|

最后增加一行 `合计`，统计：

- 器件总数量；
- 贴片焊点总数；
- 直插焊点总数；
- 总焊点数写在备注列或最后一列中。

## 5. 封装/类型写法标准

封装列只写焊接人员真正需要的信息，**禁止把 BOM 中完整 Footprint 字符串、电气参数、厂商库名全部塞进封装列**。

优先使用准确的器件类别名称，而不是笼统写“连接器”。已知型号存在明确类别时，必须写出类别。

统一规则：

| 器件 | 封装列写法 |
|---|---|
| 0805 电阻/电容 | `0805` |
| 0603 电阻/电容 | `0603` |
| SOP-8 | `SOP-8` |
| `DBT10-7.62-6P-GN`（U1/U2） | `7.62mm栅栏式接线端子` |
| `DB127V-5.0-3P-GN-S`（J1/J2） | `5.0mm螺钉式接线端子` |
| 其他已知类型的接线端子 | 写准确类别，如 `栅栏式接线端子`、`螺钉式接线端子`、`插拔式接线端子` |
| 类型无法确认的普通接插件 | `连接器` |
| DB44 公头 | `DB44公头` |
| DB44 母头 | `DB44母头` |
| DB78 公头 | `DB78公头` |
| DB78 母头 | `DB78母头` |
| 插件电阻 | `插件` |
| 其他直插件 | 优先写简短通用名称，如 `插件`、`排针`、`端子` |

例如：型号列保留 `DBT10-7.62-6P-GN`，封装/类型列写 `7.62mm栅栏式接线端子`；型号列保留 `DB127V-5.0-3P-GN-S`，封装/类型列写 `5.0mm螺钉式接线端子`。

## 6. 焊点统计标准

### 6.1 贴片器件

- 两端贴片 R/C/L：每只 2 个贴片焊点；
- SOP-8：每只 8 个贴片焊点；
- 其他 IC：按实际引脚数统计。

### 6.2 直插件

- 插件电阻：每只 2 个直插焊点；
- 普通端子：按实际针脚数统计；
- D-Sub/DB 连接器：信号针全部统计；
- **连接器固定脚/外壳焊脚默认计入焊点**，除非用户明确说不计；
- 例如 DB44 若有 44 个信号脚 + 2 个固定脚，则按 46 个直插焊点统计。

### 6.3 测试点

**默认不计入焊接清单，也不计入焊点总数。**

除非用户明确说测试点需要焊接，才单独加入。

### 6.4 机械件

- 安装孔、螺丝孔不算焊点；
- 纯机械固定件不算焊点；
- 若外壳脚实际需要焊接，则按焊接脚计入。

## 7. 表格样式标准

以后统一使用简洁样式：

- 背景以白色为主；
- 标题可加粗；
- 表头使用浅灰色；
- 不使用多种高饱和颜色；
- 正文黑色字体；
- 使用细边框；
- 数量、焊点列居中；
- 自动换行；
- 列宽以不截断主要信息为准；
- 冻结标题/表头；
- 不使用装饰性图标、渐变、彩色分组块。

推荐外观：**黑字 + 白底 + 浅灰表头 + 细黑/灰边框**。

## 8. 内容写法标准

- 位号写成 `R2, R3, R4`，不要粘成一串；
- 相同型号、相同封装、相同焊接方式可以合并一行；
- 型号相同但封装不同必须拆开；
- 阻值不同必须拆开；
- 已知连接器/端子类别时必须写准确名称，不笼统写“连接器”；
- 不把 Net Label、Power Port、CAD 对象名写入焊接清单；
- 不把测试点写入清单，除非用户明确要求；
- 备注只写真正有装配价值的信息，例如 `含2个固定脚`、`注意方向`、`大电流焊盘建议充分上锡`。

## 9. 生成后自检

交付前检查：

1. Sheet 只有 `焊接清单`，除非用户另有要求；
2. 封装是否已简化；
3. 已知端子/连接器类别是否写成准确名称；
4. 测试点是否被排除；
5. 连接器固定脚是否按用户规则计数；
6. BOM 与原理图是否存在漏项；
7. 器件数量合计是否正确；
8. 贴片焊点、直插焊点、总焊点是否正确；
9. 表格是否简洁，无多余彩色样式；
10. Excel 可正常打开，无公式错误。

## 11. 交付前强制三重全面审核闭环

完成 Excel 后，**不得直接交付**。必须执行以下三重审核，并形成闭环：

### 11.1 第一审：主代理自行全面审核

主代理必须从头到尾重新检查全部输入资料与全部输出内容，至少覆盖：

- BOM 与原理图逐项一致性；
- 是否漏器件、重复器件、错位号；
- 型号、规格、封装/类型名称；
- 贴片/直插属性；
- 单件焊点数与数量乘积；
- 固定脚/外壳脚统计；
- 测试点、机械孔是否按规则排除；
- 合计公式和总焊点；
- Sheet、列结构、表头、备注；
- 配色、列宽、换行、可读性；
- 文件能否正常打开、是否存在公式错误。

### 11.2 第二审、第三审：两个独立子代理分别全面审核

必须另外启动 **2 个彼此独立的子代理**，分别对最终文件做完整审核。

要求：

- 两个子代理都必须获得完成审核所需的原理图、BOM、用户规则和最终 Excel；
- 每个子代理都必须独立从头检查整份文件；
- 可以给两个子代理不同的重点，例如一个偏数据/焊点统计，一个偏资料一致性/格式，但**两者都必须覆盖全部检查项，不能只做专项抽查**；
- 不得把主代理或另一个子代理的“已检查结论”当成免检依据。

如果当前运行环境确实不支持子代理，禁止假装已经执行；必须明确告诉用户该步骤未能执行。

### 11.3 发现问题后的重审规则

任意一次审核只要发现问题：

1. 先修正问题；
2. 修正后将此前审核结果全部视为失效；
3. **重新从第一审开始，主代理 + 两个子代理全部再做一轮完整审核**；
4. 新一轮审核仍必须从头到尾检查全部项目，不能只复查刚改的位置；
5. 若再次发现问题，继续“修改 → 三方全部全面重审”；
6. 直到主代理和两个子代理在同一最终版本上都确认没有问题，才能交付。

### 11.4 禁止增量式/记忆式免检

每一轮、每一个审核者都必须执行**全量重新审核**。

禁止以下做法：

- “上一轮这里看过了，这轮不再检查”；
- “只检查修改过的行”；
- “另一个审核者已经检查过，所以我跳过”；
- “只抽查部分器件或部分 Sheet”；
- 因为历史版本正确，就默认最终版本对应区域仍正确。

**审核对象永远是当前最新完整文件，而不是修改差异。**

## 12. 最终交付条件

只有同时满足以下条件才能给用户下载链接：

- 主代理全面审核通过；
- 子代理1全面审核通过；
- 子代理2全面审核通过；
- 三者审核的是同一份最终文件；
- 最近一次审核后没有再修改文件。

若存在未确认问题，应先询问用户，不得以“待确认 Sheet”代替确认。
