# PCB 焊接清单生成 Skill

## 1. 目标

把一块 PCB 的设计资料和采购资料统一成一份最终可交给焊接人员使用的 `焊接清单.xlsx`。

最终清单必须同时解决 4 件事：

1. 板上到底要焊哪些器件、各多少只；
2. 最终实际使用的是哪个具体型号，包括缺货后的替换型号；
3. 贴片/直插焊点各多少，总焊点多少；
4. 哪些器件采购证据不足或数量不足，仍需要补购。

## 2. 固定原始输入：5 类资料

一次任务优先要求以下 5 类资料齐全：

```text
原始输入/
├─ 1_网表            # Altium .NET 或等价网表
├─ 2_原理图          # PDF / SchDoc 导出 PDF
├─ 3_BOM             # xlsx / xls / csv
├─ 4_采购表          # 下单表、立创导出表等 xlsx / xls / csv / pdf
└─ 5_发票            # pdf，作为实际采购型号与数量的证据
```

### 各资料职责

- **网表**：器件位号、实际装配器件集合、网络连接；是“板上有哪些器件”的硬依据。
- **原理图**：器件用途、引脚、接口、DNP/机械件判断、特殊器件语义；用于核对网表/BOM。
- **BOM**：原设计选型、标称值、参数、封装、原始具体型号。
- **采购表**：实际下单型号、缺货替换型号、采购数量；若有明确“原型号 → 新型号”映射，以该映射更新最终型号。
- **发票**：确认实际采购过的型号和数量。采购表与发票若属于同一笔订单，**不得重复累加数量**。

资料冲突时不得静默猜测。无法确认的型号映射、封装、数量或替换关系必须先标为待确认，必要时询问用户。

## 3. 资料优先级与替换型号规则

### 3.1 位号与板上数量

优先级：

```text
网表 + BOM 一致 > 仅 BOM
```

网表与 BOM 位号集合不一致时必须列出差异，不得直接生成最终清单。

### 3.2 最终实际型号

优先级：

```text
用户明确指定替换
    > 采购表中明确的替换型号
    > BOM 原始型号
```

发票用于验证“是否采购”和“采购数量”，不能在没有映射依据时仅凭相似名称擅自把某料号替换成另一料号。

如果发生替换，最终清单中的规格参数必须对应**新型号**，不能继续沿用旧型号独有参数。

### 3.3 采购/补购判断

先将采购表和发票去重、归一化成实际采购证据，再比较：

```text
需要数量 = PCB 实际装配数量
可用数量 = 明确到货数量（若有）
         否则使用去重后的已采购数量
缺口数量 = max(需要数量 - 可用数量, 0)
```

- 缺口为 0：`补购状态` 留空，不写“已到货”。
- 缺口 > 0：写 `待补购 N只`，并将整行浅黄色高亮。
- 已知库存若没有出现在这 5 类资料中，不能凭空假设存在。

## 4. 内部标准化文件

原始 5 类资料先由主代理整理为固定中间输入，再交给 Python 计算。

```text
input/
├─ bom.csv
├─ component_rules.csv
└─ procurement.csv
```

### 4.1 `bom.csv`

固定列：

```csv
Designator,Nominal,ResolvedDescription,Footprint,DesignModel,FinalModel
C34,1uF,"精度:±20%;额定电压:50V;纹波电流:8mA@120Hz;",CAP-SMD_BD4.0-L4.3-W4.3,RST50V1M4X5,RVT1H1R0M0405
C42,1uF,"精度:±20%;额定电压:50V;纹波电流:8mA@120Hz;",CAP-SMD_BD4.0-L4.3-W4.3,RVT1H1R0M0405,RVT1H1R0M0405
```

要求：

- 一行一个实际器件位号；
- `Designator` 全表唯一；
- `DesignModel` 为原设计型号；
- `FinalModel` 为最终实际焊接型号；无替换时二者相同；
- `ResolvedDescription` 必须描述 `FinalModel`，发生替换后不要保留旧型号独有参数；
- 测试点、机械孔等是否进入焊接清单由规则表决定。

### 4.2 `component_rules.csv`

固定列保持：

```csv
MatchField,MatchValue,DisplayPackage,MountType,PinsPerPart,FixedPinsPerPart,Include,Notes
Footprint,R0805,0805,SMD,2,0,yes,
Model,DSUB-M-44H,DB44公头,THT,44,2,yes,含固定脚
```

其中：

- `MatchField`：`Model` / `Footprint`；这里的 `Model` 匹配 `FinalModel`；
- `DisplayPackage`：最终 Excel 的“封装/类型”；
- `MountType`：`SMD` / `THT` / `NONE`；
- `PinsPerPart`：正常焊脚数；
- `FixedPinsPerPart`：额外固定焊脚数；
- `Include`：是否进入焊接清单。

命名规范：

- 普通阻容：`0805`、`1206`；
- SMD 铝电解统一写：**`贴片铝电解电容`**；
- THT 铝电解统一写：`直插铝电解电容`，必要时后接脚距；
- 连接器、开关、模块写可被焊接人员直接识别的名称。

匹配优先级：`FinalModel` 精确规则 > `Footprint` 精确规则。无规则必须 FAIL。

### 4.3 `procurement.csv`

固定列：

```csv
Model,PurchasedQty,ReceivedQty,Source,Notes
RVT1H1R0M0405,20,20,"采购表+发票",
OPA197ID,0,,"采购表+发票","未发现采购记录"
```

含义：

- `Model`：必须与 `FinalModel` 使用同一归一化料号；
- `PurchasedQty`：采购表和发票去重后的已采购数量；
- `ReceivedQty`：若资料中存在明确到货数量则填写，否则留空；
- `Source`：采购证据来源；
- 同一订单在采购表和发票各出现一次时，只算一次，不允许相加。

## 5. 型号/规格列格式

最终“型号/规格”必须简洁、可采购、无重复字段。

错误：

```text
标称值/名称：10nF；容值:10nF；精度:±10%；...
```

正确：

```text
10nF；精度:±10%；额定电压:50V；温度系数:X7R；具体型号：CL21B103KBANNNC
```

电阻示例：

```text
11.3kΩ；电阻类型:薄膜电阻；精度:±0.1%；功率:125mW；工作电压:100V；温度系数:±25ppm/℃；具体型号：ERA-6AEB1132V
```

规则：

- 第一段只写一次标称值/器件名；
- 删除与第一段重复的 `容值/阻值/电感值`；
- 保留对焊接/采购有意义的精度、耐压、功率、电流、温漂等；
- 最后固定写 `具体型号：xxx`；
- 不在最终清单中写“来源：某 BOM”之类过程信息。

## 6. 合并同一实际物料

只要以下字段全部一致，就必须合并为同一行：

```text
FinalModel
+ 最终规格
+ DisplayPackage
+ MountType
+ PinsPerPart
+ FixedPinsPerPart
+ 补购状态
```

位号使用逗号合并，数量自动累加。

例如 C34 原型号为 `RST50V1M4X5`，若最终确认与 C42 都改用 `RVT1H1R0M0405`，则输出：

```text
位号：C34, C42
型号/规格：1uF；精度:±20%；额定电压:50V；...；具体型号：RVT1H1R0M0405
封装/类型：贴片铝电解电容
数量：2
```

不能因为原 BOM 型号不同而强行拆成两行。

## 7. 固定计算

所有数量和焊点由 Python 独立计算：

```text
Quantity = Designator 数量
PerPartJoints = PinsPerPart + FixedPinsPerPart
SMDPoints = Quantity × PerPartJoints   # SMD
THTPoints = Quantity × PerPartJoints   # THT
TotalJoints = ΣSMDPoints + ΣTHTPoints
```

LLM 不进行数量乘法和总焊点汇总。

## 8. 最终输出

对用户只需要交付：

```text
output/
└─ soldering_table.xlsx
```

内部仍生成 `validation_report.md` 作为审计文件，但默认不要求用户使用。

`焊接清单` Sheet 固定 8 列：

| 位号 | 型号/规格 | 封装/类型 | 数量 | 贴片焊点 | 直插焊点 | 备注 | 补购状态 |
|---|---|---|---:|---:|---:|---|---|

### 样式固定

- 白底、黑字；
- 浅灰表头；
- 细边框；
- 自动换行；
- 冻结首行；
- 合计行浅灰、加粗；
- 文本较长的“型号/规格”列加宽；
- `待补购` 行整行浅黄色高亮；
- 无缺口的 `补购状态` 单元格留空。

## 9. 固定脚本

运行：

```bash
python scripts/build_soldering_table.py input output
```

脚本必须检查：

- 3 个中间 CSV 均存在且列完整；
- BOM 位号唯一；
- `FinalModel` 非空；
- 每个器件命中唯一焊接规则；
- SMD/THT/NONE 合法；
- pin 数、固定脚数、采购数量均为非负整数；
- 采购型号不能重复计数；
- 数量、焊点、补购缺口全部由 Python 计算；
- Excel 生成后重新打开并逐行回读比对；
- 合计行再次比对。

全部通过才允许输出 `PASS`。

## 10. 主代理职责

主代理负责：

1. 读取并交叉核对网表、原理图、BOM、采购表、发票；
2. 展开 BOM 中合并位号，形成一行一位号；
3. 识别缺货后的替换型号，建立 `DesignModel → FinalModel`；
4. 用新型号参数更新 `ResolvedDescription`；
5. 将采购表和发票去重，生成 `procurement.csv`；
6. 根据原理图/封装判断 SMD/THT、固定脚、连接器类型；
7. 生成中间 CSV 后调用脚本；
8. 对最终 Excel 做语义复核。

主代理不得：

- 猜测不存在的具体型号；
- 把发票和采购表中的同一订单重复计数；
- 用旧型号参数描述新型号；
- 手工计算数量或总焊点；
- 因器件未采购而从焊接清单中删除该器件。

## 11. 交付审核

脚本 PASS 后，主代理必须再完整检查：

- 位号是否覆盖全部实际装配器件；
- 相同最终料号是否已正确合并；
- 型号/规格是否无重复开头；
- `贴片铝电解电容` 等命名是否统一；
- 未采购器件是否仍保留，并正确标 `待补购 N只`；
- 已覆盖采购的器件是否没有多余状态文字；
- 总器件数、SMD/THT 焊点和总焊点是否合理。

若环境支持子代理，再执行两个独立完整审核；任何修改都会使之前审核失效，修改后重新运行脚本并重新审核。

最终只有在 `validation_report.md = PASS` 且语义审核通过后才能交付。
